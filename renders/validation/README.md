# Validation Renders

Generated by `scripts/validate_bakes.py`.

## Bake Settings

- Validation resolution: `128`
- Frames rendered: `40, 80, 120, 160, 200`
- Outward smoke baked: `True`
- Rocket trail baked: `True`

The production scene keeps the tutorial-style resolution of `196`; these
validation caches are intentionally lower resolution so the end-to-end
workflow can be verified quickly.

## Reference Comparison

- `frame_040.png`: launch start, before most visible smoke/fire.
- `frame_080.png`: early outward burst and first rocket trail activity.
- `frame_120.png`: broad ground smoke spread, comparable to the tutorial's outward smoke preview section.
- `frame_160.png`: mid-trail check for fire/smoke continuity.
- `frame_200.png`: final launch height and full trail coverage.

Compare these against `reference/keyframes_contact_sheet.jpg` and the
individual keyframes under `reference/keyframes/`. The sampled tutorial
frame `frame_07_09-54.jpg` appears to be an unrelated ad frame and should
not be used as a visual target.

## Issue 10 Polish Notes

The medium-resolution validation pass is closer than the first low-resolution
pass: the fire is less blown out, the trail smoke is more visible through the
flame, and the baked scene remains reproducible from script plus assets.
Remaining differences from the tutorial PV are mostly visual parity items:
the validation render uses the final outdoor camera/HDRI setup while the
tutorial material previews use a darker viewport-style render, and the
ground smoke still reads softer and less chunky than the tutorial's broad
rolling base plume.

## Preview Animation

After validation frames exist, a short preview animation can be rendered
from Blender with:

```powershell
& "C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe" --background renders\validation\rocket_launch_validation.blend --render-output renders\validation\preview_ --render-format PNG --frame-start 40 --frame-end 120 --render-anim
```
